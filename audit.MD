A. Executive SummaryThis report presents an independent, code-level engineering and performance audit of the Flux Download Manager codebase (snapshot 349cbc43f949fee02cf578c277a496247724dce3). Every C++20 source and header file (src/**), browser extension script (extension/**), build/packaging script (CMakeLists.txt, Makefile, installer/*, scripts/*), and test suite (tests/**) was inspected directly. Safe offline verification was executed against the unaltered source tree.Project & Working Tree Inspection SummarySource Snapshot State: The provided project archive is a snapshot of commit 349cbc43f949fee02cf578c277a496247724dce3 (without a .git directory or uncommitted working-tree diff). All source files remain untouched.Protocol Implementation Reality vs. Claims:HTTP/HTTPS (src/brisk_engine/): Genuinely implemented with multi-segment range scheduling and dynamic work-stealing, WinHTTP (Windows) and OpenSSL/socket (POSIX) clients, ETag/Last-Modified validation, and DPAPI/AES-256-GCM credential encryption at rest. However, it contains two race conditions in work-stealing/rollback that can corrupt downloaded files, zero connection or TLS session reuse across probes/segments, a cross-origin redirect credential leak, broken automatic retry error matching, and unthrottled single-stream progress callbacks.HLS/DASH/YouTube (src/engine_stream/, src/worker_stream/): Nm3u8dlReAdapter is genuinely implemented to drive an external N_m3u8DL-RE + ffmpeg + yt-dlp pipeline. However, the repository also builds an in-tree C++ executable named N_m3u8DL-RE (src/worker_stream/nm3u8dl_re_worker.cpp) that emits a hardcoded fake speed (5.00MBps), downloads only the first 3 segments of standard MPEG-DASH <SegmentTemplate> manifests, uses an RFC-noncompliant HLS AES-128 default IV, ignores --drop-video/--drop-audio and container format flags (causing audio-only and .webm/.ts stream downloads to fail), and bypasses SSRF and local-file guards.FTP (src/engine_ftp/): Partially implemented single-connection client (EPSV/PASV/REST/RETR), but pausing an active FTP download returns Result::Ok(total_written), causing DownloadController to rename the truncated .part file to the final filename and mark the task COMPLETED. It also treats premature control-connection drops as success, bypasses SHA-256 verification and ConflictPolicy, loses progress on failure, leaks .part files on cancel, and is vulnerable to CRLF command injection and PASV third-party bounce. Moreover, the UI's Add Download dialog (DesktopView::SubmitAddDownloadDialog) explicitly rejects ftp://, magnet:, and rtsp:// URLs.BitTorrent (src/engine_torrent/): Only a single-peer sequential prototype is implemented. Magnet links (magnet:?xt=urn:btih:...) always fail immediately with ERR_TORRENT_MALFORMED because neither BEP 9 (ut_metadata) nor DHT (BEP 5) exists. Local .torrent files dropped onto the UI fail in DownloadController::AddTask (HttpClient::ParseUrl rejects local paths), while remote .torrent URLs fail in RunTaskWorker (TorrentParser::ParseTorrentFile opens local_task.url as a local filesystem path). Pausing a torrent marks it FAILED, and piece bitfields are never persisted.RTSP/MMS/RTMP (src/engine_stream/rtsp_mms_adapter.cpp): Wraps ffmpeg on Windows (and is a non-functional stub returning ERR_STREAM_EMPTY on POSIX), interpolates task.url into CreateProcessW without escaping quotes (enabling FFmpeg argument injection), and overwrites partial captures from byte 0 on resume.Summary of
