## Definitions

- **Atomic File Replacement:** The filesystem operation of writing all in-progress download data to a temporary file (`<filename>.openidm.part`) in the target directory (same volume) and, only after all bytes and optional checksums are verified, renaming it to the final destination filename via `SetFileInformationByHandle` (`FileRenameInfoEx`) so the user never observes a half-written target file.
- **Checksum:** A cryptographic or integrity digest (`SHA-256`, `SHA-1`, or `MD5`) computed over a completed download file using Windows CNG (`BCryptHash`) to verify byte-level accuracy against a publisher-provided digest.
- **Content Script:** A JavaScript/TypeScript file declared in the browser extension manifest (`content_scripts`) or injected via `chrome.scripting.executeScript` that runs in an **isolated JavaScript execution world (`ISOLATED`)** while sharing access to the webpage's DOM tree. Used by OpenIDM to observe `<video>` elements and render the closed Shadow DOM download button.
- **Cookies:** HTTP state management headers (`Cookie` request header / `Set-Cookie` response header) associated with an origin. Many authenticated downloads and video manifests require the browser's session cookies to avoid `401 Unauthorized` or `403 Forbidden` responses when fetched by the desktop engine.
- **DASH (Dynamic Adaptive Streaming over HTTP):** ISO/IEC 23009-1 adaptive bitrate streaming standard. Uses an XML **Media Presentation Description (`.mpd`)** manifest to describe `Period`, `AdaptationSet` (video, audio, subtitles), `Representation` (resolution/bitrate variants), initialization segments (`_init.mp4`), and media segments (`.m4s`).
- **DRM (Digital Rights Management):** Cryptographic content protection systems (such as Google Widevine, Microsoft PlayReady, Apple FairPlay, and MPEG-CENC `SAMPLE-AES-CTR` with license servers) that restrict access to decryption keys via a Content Decryption Module (CDM). **OpenIDM strictly prohibits bypassing DRM or extracting CDM keys (`NFR-015`).**
- **Dynamic Connection Reuse (Work-Stealing Byte-Range Split):** The algorithm—pioneered in [Brisk](https://github.com/BrisklyDev/brisk)—where a segment worker that finishes downloading its assigned byte range `[A, B]` does not terminate if other workers still have large remaining ranges; instead, the scheduler splits the largest remaining range `[C, D]` at its midpoint `M` and assigns `[M+1, D]` to the newly idle worker.
- **Dynamic Connection Spawning:** Starting an ordinary HTTP download with a single connection (`Segment 0`) and progressively opening additional connections (`1 .. N-1`) only after byte-range support (`206 Partial Content`) is confirmed and transfer size/speed justifies parallel connections.
- **Fragment / Segment:** A discrete time-sliced media chunk in an adaptive stream (commonly `.ts` MPEG-2 Transport Stream files or `.m4s` / `.mp4` CMAF fragmented MP4 chunks) referenced by an HLS `.m3u8` or DASH `.mpd` manifest.
- **HLS (HTTP Live Streaming):** Apple's adaptive bitrate streaming protocol (RFC 8216). Uses UTF-8 Extended M3U playlists (`.m3u8`), divided into **Master Playlists** (which list variant streams via `#EXT-X-STREAM-INF` and alternate audio/subtitle renditions via `#EXT-X-MEDIA`) and **Media Playlists** (which list sequential `.ts` or `.m4s` media segments via `#EXTINF` and optional `#EXT-X-MAP` initialization segments).
- **HTTP Range Requests:** RFC 9110 (formerly RFC 7233) mechanism where an HTTP client sends `Range: bytes=<start>-<end>` and a range-capable server responds with `206 Partial Content` and `Content-Range: bytes <start>-<end>/<total_length>`.
- **Job Object (Windows):** A Windows kernel object (`CreateJobObjectW`) that groups one or more processes as a unit. Configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, it guarantees the OS kernel immediately terminates all child worker processes (`N_m3u8DL-RE.exe` and `ffmpeg.exe`) if `openidm.exe` closes or crashes.
- **Manifest:** A structured index file (`.m3u8` for HLS, `.mpd` for DASH, `.ism`/`.ismc` for Microsoft Smooth Streaming) that describes available video/audio/subtitle tracks, bitrates, segment URLs, and timing for a streaming video.
- **MSE (Media Source Extensions):** W3C browser API (`MediaSource` and `SourceBuffer`) allowing JavaScript players (such as `hls.js`, `dash.js`, and Shaka Player) to fetch raw media segments via `fetch()`/`XHR` and feed byte buffers into an HTML `<video>` element via a synthetic `blob:https://...` URL. Because a `blob:` URL backed by a `MediaSource` handle is a live in-memory pipeline rather than a static file, **the `blob:` URL itself cannot be downloaded directly**; instead, OpenIDM captures the underlying `.m3u8`/`.mpd` manifest URL requested over the network.
- **Muxing (Multiplexing):** The process of interleaving separate elementary or container-wrapped video (`.mp4`/`.ts`), audio (`.m4a`/`.aac`), and subtitle (`.srt`/`.vtt`) tracks into a single synchronized output container (`.mp4` or `.mkv`) without re-encoding video/audio frames (`-c copy` in FFmpeg).
- **Named Pipe (Windows):** A kernel-managed inter-process communication channel (`\\.\pipe\OpenIDM_IPC_<UserSID>`) protected by a Windows Security Descriptor (DACL). Used by OpenIDM for high-speed, authenticated local communication between `openidm-nmh.exe` and `openidm.exe`.
- **Native Messaging:** The standard browser extension API (`chrome.runtime.connectNative` / `browser.runtime.connectNative`) where the browser spawns a registered local executable (`openidm-nmh.exe`) and exchanges 32-bit length-prefixed UTF-8 JSON messages over standard input (`stdin`) and standard output (`stdout`).
- **Ordinary File Download:** Any HTTP/HTTPS transfer of a complete, self-contained file (e.g., `.zip`, `.iso`, `.exe`, `.pdf`, or a progressive `.mp4`/`.webm` video file) that does not require manifest parsing or multi-track muxing.
- **Referer:** The `Referer` (and `Origin`) HTTP request header indicating the webpage or player frame URL that initiated a resource request. Frequently validated by CDNs to block unauthorized hotlinking.
- **Resume:** Continuing a paused or interrupted download from previously persisted byte offsets (`.openidm.part` + SQLite `task_segments` records) after validating that the remote resource has not changed (`ETag` / `Last-Modified`).
- **Retry:** Automatically re-establishing a failed HTTP byte-range request or segment fetch after a transient network error (`WINHTTP_ERROR_TIMEOUT`, `502`, `503`, `504`, `429`) using exponential backoff with jitter.
- **Segmented Downloading:** Splitting a single ordinary file of known `Content-Length` into multiple non-overlapping byte intervals (`[start_offset, end_offset]`) downloaded concurrently over independent HTTP connections and written to their exact offsets in a pre-allocated `.openidm.part` file.
- **Service Worker (Extension Background):** The event-driven background execution context in a Manifest V3 browser extension (`background.service_worker` in Chromium). It observes `webRequest` and `downloads` events and communicates with the Native Messaging Host, suspending when idle and waking on browser events.
